# Lurume P8 批量文件夹导入与 Zotero 迁移计划

日期：2026-08-31

状态：**计划已讨论并按首次审查修订，尚未开始实现。** P8 必须按本文检查点顺序推进；每个检查点通过后暂停，
不得因为计划已经写完而直接一次性完成全部实现。

## P8 目标

P8 让已有论文目录或 Zotero 文献库的用户能够把现有资料带入 Lurume，而不必逐个选择 PDF、
手工重建分类或把文件交给云端服务。

P8 提供两条明确分开的导入路径：

```text
已有分类文件夹
→ 用户选择根目录
→ 后台递归扫描与 PDF 校验
→ 目录树映射为嵌套文献集
→ 原位引用 PDF
→ 预览确认后整批发布

本机 Zotero
→ 用户明确启动迁移
→ 专用 XPC 只读访问 Zotero Local API
→ 映射文库、文献集、条目、元数据与 PDF 附件
→ 用户授权 Zotero 文件位置和 Lurume 目标目录
→ 暂存、复制并校验 PDF
→ 预览确认后整批发布
```

P8 的成功标准不是建立文件同步器或复制一个完整的 Zotero，而是完成一次**可预览、可取消、
可重复执行、不会静默覆盖或删除用户数据**的本地迁移。导入期间既有 PDF 阅读、搜索、翻译、
高亮、笔记和文献库管理必须继续可用。

## 已确认的产品裁决

- 普通文件夹导入原位引用 PDF，不复制、移动、重命名或修改原文件。
- Zotero 迁移把 PDF 复制到用户明确选择的 Lurume 文献目录；原 Zotero 文件保持不变。
- P8 将 P5 的扁平文献集升级为嵌套文献集，文件夹和 Zotero collection 层级均原样表达。
- Lurume 继续保持“一条文献记录对应一个 PDF”，不在 P8 引入多附件阅读模型。
- Zotero 一条书目记录挂有多个 PDF 时，每个 PDF 分别成为一条 Lurume 文献，共享父条目的
  元数据和文献集归属，并用独立的附件标签区分。
- P8 同时扩展通用引用元数据模型；数据层不保存一份只能由 Zotero 解释的完整 JSON。
- 去重使用来源标识、现有文件身份与 PDF SHA-256；标题、作者或 DOI 相似不触发静默合并。
- 再次导入是一次性、增量、非破坏性的导入，不是镜像或持续同步。外部删除不会传播到
  Lurume。
- 扫描和预览阶段只读；用户确认后先完成候选事务，最后整批一次发布。
- 删除一个用户文献集时递归删除其整个分类子树和归属关系，但不删除论文记录、PDF、高亮、
  笔记或阅读位置；撤销恢复完整子树。
- 文献表格继续保持紧凑；扩展字段进入详细元数据编辑器，普通搜索覆盖常用标识与出版信息。

## P8 不改变的底线

- 原 PDF 始终属于用户。文件夹导入、重导、文献集操作和移除文献都不得修改原 PDF 字节。
- Zotero 迁移产生的目标 PDF 位于用户可见且明确选择的目录中。从 Lurume 移除记录仍不自动
  删除这些文件。
- 主 App 不获得互联网访问能力。Zotero 网络访问只存在于新的专用 localhost XPC 中。
- Zotero XPC 不读取文件、Keychain 或用户目录，不向 Zotero 执行任何写操作。
- P7 Translation XPC 继续只负责 OpenAI-compatible 翻译，不得兼任 Zotero 导入服务。
- P6 Sparkle 更新、P7 翻译与 P0–P5 文献数据失败边界保持相互独立。
- 没有显式用户手势时，Lurume 不探测 Zotero、不扫描目录、不计算哈希，也不启动导入 XPC。

## 用户入口与整体流程

“文件”菜单和文献库工具栏提供三个区分明确的入口：

```text
导入 PDF…
导入文件夹…
从 Zotero 迁移…
```

现有“导入 PDF”继续支持单个和多个 PDF，并复用 P8 的文件校验与去重核心，但不强制经过大型
迁移向导。“导入文件夹”和“从 Zotero 迁移”进入统一的分步向导：

1. 选择来源；
2. 扫描并读取必要元数据；
3. 选择目标父文献集；Zotero 路径额外选择目标文件目录；
4. 查看层级、容量、重复项、缺失文件、冲突和跳过项；
5. 对需要人工决定的冲突逐项或批量选择；
6. 明确确认后执行；
7. 显示新增、复用、跳过、冲突、失败和复制字节数的结果报告。

关闭向导、切换文献或隐藏窗口不会隐式确认导入。扫描阶段可以随时取消；执行阶段的取消先
停止调度新任务，等待当前不可分割的文件操作结束，再按事务规则清理。

## 文献库 schema v5

当前正式文献库为 v4。P8 将其升级为 v5，并继续保留 v1–v4 的显式解码结构，不通过给当前
类型增加默认值来伪装迁移。

### 嵌套文献集

`CollectionRecord` 在稳定 `id`、名称和创建时间之外增加：

- `parentID: UUID?`：`nil` 表示顶层；
- 零个或多个稳定导入来源标识；用户明确合并不同来源文献集时保留全部来源；
- 导入时的来源名称和层级版本信息，仅用于重导差异判断；
- 用户是否在 Lurume 中手动改名或移动的标记。

文献集校验必须满足：

- 每个非空 `parentID` 都引用同一快照中的有效文献集；
- 父子图无自环、无多节点循环；
- 名称去除首尾空白后非空；
- 名称唯一性只在同一父级内按现有本地化、不区分大小写规则检查；
- 系统来源“全部文献”和“未分类”不进入 `CollectionRecord`，也不能成为父节点；
- 导入来源标识若存在，必须能稳定解码，但来源不可用不使文献库进入只读保护。

v4 的全部文献集迁移为 `parentID == nil` 的顶层节点。论文 ID、文献集 ID、成员关系、选择、
排序偏好和创建时间原样保留。

### 通用引用元数据

P8 将现有 `title / authors / year` 扩展为与来源无关的 `BibliographicMetadata`。至少包含：

- 文献类型：期刊论文、会议论文、预印本、学位论文、书籍、书籍章节、报告和普通文档；
- 标题；
- 结构化创作者数组；
- 完整原始发表日期和可用于显示、排序的规范化年份；
- 容器标题：期刊、会议论文集或书名；
- 卷、期、页码；
- DOI、ISBN、ISSN、arXiv 等类型化标识符；
- 出版社、出版地、版本；
- URL、语言和摘要。

#### 唯一标题字段与现有 `displayName`

当前 v4 `PaperRecord` 没有持久化的 `displayName` 字段；`displayName` 只是初始化器用来填充现有
`title` 的参数，v1 legacy 解码类型中的 `displayName` 也早已在迁移时转换为 `title`。P8 不得
重新制造两个可分叉的标题字段：

- v5 唯一持久化书目标题为 `BibliographicMetadata.title`；
- `PaperRecord.title` 若在检查点一为减少调用点改动而暂时保留，只能是转发到
  `metadata.title` 的非 Codable 兼容访问器，不能再次存储一份值；
- 现有表格、阅读侧栏、搜索、排序、详情和无障碍标签都读取同一个书目标题；
- 现有内联改名与详细编辑器修改同一个标题，并写入标题手动覆盖标记；
- 文件夹、单 PDF 和 Zotero 导入都写入该字段；Zotero 附件标签只负责区分附件，不与标题竞争；
- 标题为空时，界面按现有规则从原始文件名生成只读回退显示；用户提交空标题时仍记录手动
  清空决定，后续自动元数据不得静默覆盖；
- v5 初始化器把现有 `displayName` 参数改名为 `initialTitle` 或等价名称，避免把构造参数误解
  为第二个数据属性。

创作者记录至少保存角色、名、姓和单字段机构/团体名。角色第一版展示作者、编辑和译者；
遇到其他 Zotero 角色时保留稳定角色字符串并在详细编辑器中显示为“其他”，不得丢弃姓名。

日期同时保存去空白后的来源文本和能够可靠解析出的年份。无法完整解析的日期不报废整条
文献，只保留原文并让年份为空。标识符保存规范化比较值与用户可见值；DOI 比较时去除常见
`doi:` 和 `https://doi.org/` 前缀，但不得把 URL 查询参数或任意字符串误当 DOI。

每个可编辑字段都有明确的手动覆盖标记。创作者数组作为一个原子字段处理；P8 第一版不尝试
逐个作者合并。手动清空也属于用户决定，之后的 PDF 属性读取或 Zotero 重导不得把字段复活。

v4 迁移规则：

- 标题原样进入新标题字段；
- 现有作者字符串作为一个未拆分的 literal author 保存，避免猜测逗号究竟分隔作者还是姓与名；
- 年份进入规范化年份；
- 三个既有手动编辑标记映射到新字段标记；
- PDF 属性自动读取状态原样保留；
- 新字段、哈希和来源标识为空；迁移时不打开 PDF、不计算哈希、不访问 Zotero。

### 一条记录对应一个 PDF

`PaperRecord` 继续持有唯一文件身份、安全作用域书签、原始文件名、页码和阅读状态。P8 增加：

- `metadata: BibliographicMetadata`；
- `attachmentLabel: String?`，只用于区分同一 Zotero 父条目的多个 PDF；
- 可选 `contentSHA256` 及计算时观察到的字节数和修改时间；
- 零个或多个稳定导入来源标识；相同内容由不同入口导入时保留全部来源别名；
- 最近一次成功导入时的非手动元数据快照摘要，用于差异预览。

多个 Zotero PDF 不共享 Lurume 论文 ID。高亮、笔记、阅读位置和文件恢复继续自然归属于各自
PDF，P8 不迁移这些数据到附件层。

### 导入来源标识

来源标识以去重、稳定排序的数组保存，只包含重导和诊断所需的最小字段：

- 文件夹：根目录文件身份、子目录相对路径或稳定目录身份；
- Zotero 文献集：library 类型与 ID、collection key；
- Zotero 文献：library 类型与 ID、parent item key、attachment key；
- Zotero server ID 仅作为诊断和实例变化提示，不作为唯一去重键。

来源标识不得包含 Zotero API Key、账户密码、完整原始 JSON、PDF 正文或绝对路径副本。实际
文件访问仍依赖单独的安全作用域书签。

## 嵌套文献集行为

- 旧文献集升级后全部位于顶层。
- 选中用户文献集时点击新增，默认在其下创建子文献集；选中系统来源或文献集标题时创建顶层。
- 来源栏用原生展开树显示；展开状态可以按文献集 ID 保存，失效 ID 安全丢弃。
- 文献集可以拖到另一个用户文献集下，或通过菜单移到顶层。
- 拖入自身或任意后代必须在候选快照产生前拒绝，不能先形成循环再依赖持久化报错。
- 同级按本地化、不区分大小写的名称排序；P8 不增加手动排序。
- 一篇论文可以同时直接属于任意数量、任意层级的文献集。
- 选择父文献集时，列表默认包含直接成员和全部后代成员，并按论文 ID 去重。
- 文献集计数采用相同递归语义；同一论文位于两个后代文献集时只计一次。
- “未分类”仍严格表示没有任何显式用户文献集归属，而不是“不属于当前层级”。
- 移动、改名或导入文献集只改变组织关系，不移动磁盘文件。

删除用户文献集时递归删除目标及全部后代节点，并从所有论文中移除这些 ID。确认框必须列出
将删除的文献集数量、受影响论文数量，以及“不会删除论文或 PDF”的明确说明。失去全部归属的
论文进入“未分类”；仍有其他归属的论文保持原关系。整个删除是一个撤销动作，撤销恢复完整
子树、父级、名称和论文归属。系统来源不可删除。P8 不提供同时从文献库移除子树论文的入口。

## 文件夹扫描与映射

### 来源选择与权限

“导入文件夹”使用目录选择器，获得所选根目录的只读安全作用域。扫描器只在这次显式导入期间
访问目录；发布后的每篇论文继续保存自己的安全作用域书签，根目录书签只作为重导来源记录，
不替代现有逐文件恢复边界。

扫描器：

- 递归枚举所选根目录；
- 默认跳过隐藏文件、隐藏目录、macOS package、符号链接和 Finder 替身；
- 不跟随任何可能越过授权根目录或形成循环的引用；
- 只把规范化路径仍位于授权根目录内的普通文件作为候选；
- 不只凭 `.pdf` 扩展名信任文件，必须完成最低限度 PDF 结构验证；
- 扩展名不是 `.pdf` 的文件第一版不主动探测，避免扫描任意大文件；
- 对无权限、读取失败、扫描期间消失或扫描期间变化的项目分别记录诊断；
- 不同步解析整份 PDF 正文，也不为扫描生成缩略图。

文件夹和现有“导入 PDF”的初始元数据采用同一优先级，并在预览前完成一次候选读取：

1. PDF 属性中的标题通过现有 `PaperTitleRules` 判废后可用，则作为候选书目标题；
2. 否则使用不含扩展名的文件名；
3. PDF 属性中的作者作为未拆分 literal author 候选；
4. 其他扩展引用字段为空，不从 PDF 正文、文件路径或文件名猜测期刊、日期、DOI 等信息；
5. PDF 属性读取失败不阻止有效 PDF 导入，只在报告中标记并使用文件名回退；
6. 发布记录标记本次自动属性读取已经完成，不能在导入后再次异步读取并改变用户刚确认的
   预览结果。

### 目录到文献集

- 用户所选根目录本身创建一个根文献集。
- 当前位于用户文献集时，新根文献集创建在其下；否则创建在顶层。
- 含有可导入 PDF 的子目录按原层级创建子文献集。
- 完全不含可导入 PDF 后代的空目录不创建节点。
- PDF 只直接归属其所在目录对应的文献集，不重复写入所有祖先。
- 根目录 PDF 直接归属导入根文献集。
- 父文献集通过递归展示自然包含后代论文。
- 同名目标不自动合并。预览默认生成稳定编号名称，用户可以明确选择现有节点作为合并目标。
- 同一已记录文件夹来源重导时优先复用来源 ID 对应的文献集，而不是只按名称猜测。

文件夹导入继续引用原文件。导入、重导、文献集移动和删除前后，样本 PDF 的字节哈希必须保持
不变。

## Zotero Local API 架构

### 专用 XPC

P8 新增内嵌 `LurumeZoteroImportService.xpc`，建议固定 Bundle ID：

```text
app.lurume.Lurume.ZoteroImportService
```

服务仅包含 Zotero API 请求、分页、严格 JSON 解码和来源快照组装。主 App 通过窄的
`NSSecureCoding` XPC 协议请求：

- 探测本地 API 能否使用；
- 列举本机可见文库；
- 列举指定文库的文献集；
- 分页读取指定范围的普通条目与子附件；
- 取得 PDF 附件的本地文件 URL 候选；
- 取消某次扫描。

XPC 不复制或打开文件，不读取 Keychain，不拥有用户所选文件权限，也不修改 Zotero。所有文件
路径验证、授权、哈希、复制和 Lurume 快照提交都留在主 App 的导入协调器中。

### 固定网络边界

- 唯一允许 origin 为 `http://127.0.0.1:23119`；不把 `localhost` 交给 DNS 解析。
- 基础路径固定为 `/api/`，使用 Zotero Local API v3。
- URL 由内部端点枚举和经过百分号编码的 Zotero key 构造，不接收用户输入的 Base URL。
- 只允许 `GET` 和 `HEAD`；任何写方法在协议层不存在。
- 任何跨 host、跨端口、跨 scheme 重定向在跟随前拒绝。
- `/file/view/url` 返回的 `file:` URL 只作为不可信候选数据传回主 App；XPC 不跟随或读取它。
- 响应大小、分页项数、嵌套深度和字符串长度设置明确上限；超限整页失败并给出本地化诊断。
- 请求有首字节、空闲和整体超时；取消后迟到响应由 request ID 丢弃。
- App 打开、普通文件夹导入和设置窗口都不启动该 XPC；只有用户进入 Zotero 迁移才惰性连接。
- 最后一个请求结束或取消后，客户端立即失效空闲 connection；launchd 可短期保留 CPU 空闲进程。

服务拥有 App Sandbox 与 outbound network client entitlement，但没有 network server、文件、
Keychain、个人信息、设备、Sparkle Mach lookup 或 `get-task-allow`。主 App 继续没有通用网络
client entitlement。

XPC 接受连接前沿用 P7 已验证的代码签名 requirement：固定主 App Bundle ID；Developer ID
构建再增加 Apple anchor 和相同 Team ID。ad-hoc 开发构建的局限必须在检查点文档中诚实记录。

### Zotero 可用性

Zotero 未运行、本地 API 未开启、返回 `403`、API 版本不受支持或响应 schema 无法解释时，向导
停在来源步骤并显示可操作说明，不读取 SQLite、不尝试启动 Zotero、不切到 zotero.org 云 API。

第一版兼容契约以 **Zotero Local API v3 的能力握手**为准，不只比较 Zotero 的营销版本号：

- 截至计划修订日，官方当前稳定版为 Zotero 10.0.x；检查点四和五必须至少以当时最新的
  Zotero 10.x 稳定版完成自动化与真实验收；
- Zotero 7–9 即使同样暴露 Local API v3，也只属于尽力兼容，首版不宣称完整支持；
- 未来 Zotero 主版本只有在 `/api/` 握手仍报告受支持的 API 版本、server/schema headers 可解析，
  且计划所需端点通过 capability probe 后才允许继续；不能因为版本号更高就盲目接受；
- 检查点四开始前重新核对官方当前稳定版本，并在检查点记录中列出实际测试的 Zotero 版本、
  API version、schema version 和必需端点；
- 未经验证或缺少必需端点时明确显示“不受支持”，不降级到 SQLite、导出文件或云 API。

第一版可列出本机 Zotero 中当前用户可见的个人文库和群组文库。用户可以选择整个文库或一个、
多个文献集；选择子文献集时保留其必要祖先路径和范围内的多重归属。回收站、保存搜索和仅有
搜索结果定义的动态集合不导入。

## Zotero 条目与附件映射

- 普通 Zotero 条目有一个本地 PDF：创建一条 Lurume 文献。
- 普通条目有多个本地 PDF：每个 PDF 创建独立文献，继承父条目元数据和范围内文献集归属；
  `attachmentLabel` 保存附件标题用于列表和预览区分。
- 普通条目没有本地 PDF：不创建空文献，报告为“无可用 PDF”。
- 独立 PDF 附件：创建独立文献，以附件标题、文件名和 PDF 属性组成候选元数据。
- `imported_file`、本地可用的 PDF `imported_url` 与 `linked_file` 可以导入。
- 尚未下载、文件 URL 不可解析、文件不在已授权目录或扫描期间消失的附件跳过并报告。
- 网页链接、网页快照、图片、EPUB、音视频、补充数据和其他非 PDF 附件第一版不导入。
- Zotero notes、annotations、tags、relations、saved searches、自动生成全文索引和引用键第一版
  不导入；预览和结果报告显示其数量，避免用户误以为已完整迁移。
- 既有文字处理器中的 Zotero citation links 不可能由 P8 保留，迁移确认页必须明确说明。

Zotero 父条目元数据优先于 PDF 内嵌属性。附件标题不覆盖书目标题。来源字段无法映射到 P8
通用模型时按字段计入报告，不把完整 JSON 塞进文献库。用户手动编辑过的字段在重导时始终
优先；未手动编辑字段发生变化时进入预览差异，只有用户确认才应用。

## Zotero 文件授权与目标存储

### 权限变化

当前主 App 只有 `com.apple.security.files.user-selected.read-only`。为了把 Zotero PDF 复制到用户
选择的目录，P8 必须改为 `com.apple.security.files.user-selected.read-write`。这只授权用户通过
系统选择器明确选择的来源和目标，不提供主目录、下载目录或任意路径的广泛访问。

发布预检必须锁定：

- 主 App 仍有 App Sandbox；
- 主 App 允许 user-selected read-write，但不得拥有 Downloads、Pictures、Music、Movies、
  home-relative、absolute-path temporary exception 或 generic network client；
- Zotero XPC 不得拥有任何文件 entitlement；
- Translation XPC 的文件禁用和网络边界保持不变。

### 来源目录

迁移开始时，用户通过系统选择器授权 Zotero data directory。API 返回的每个文件 URL 都要经过
标准化、符号链接解析和授权根后代检查。

对于 Zotero 外部链接附件，向导按共同祖先目录汇总无法访问的候选，并让用户逐个授权额外根
目录。用户拒绝某个目录不会扩大权限，也不终止其他项目；对应附件跳过并报告。Lurume 不把
API 返回的绝对路径直接当作授权。

### 目标目录与布局

用户选择一个可见的 Lurume 文献目录，Lurume 保存其安全作用域书签。最终布局为：

```text
用户选择的目录/
  Zotero 文库名称/
    原附件文件名.pdf
```

非法文件名字符被替换，空名称回退到稳定通用名称。重名时追加稳定编号；永不覆盖已有文件。
文献集多重归属只保存在 Lurume 快照，不为多个文献集重复复制 PDF，也不按分类树移动文件。

目标目录与全部已授权 Zotero 来源根必须在解析符号链接、标准化大小写和卷身份后彼此不重叠：

- 目标不能等于或位于 Zotero data directory、任一外部链接附件根之内；
- 任一来源根也不能位于目标目录之内；
- 发现重叠时拒绝进入复制步骤并要求重新选择，不能只显示可忽略警告；
- 用户在选择目标后又授权新的外部链接根时必须重新执行重叠校验；
- `.lurume-import-staging` 只能创建在通过上述校验的目标目录中，绝不能写进 Zotero 管理目录。

用户以后改变默认目标只影响新迁移。旧记录保留自己的文件书签并继续可恢复。从文献库移除
记录或递归删除文献集都不删除复制后的 PDF。自动清理未引用文件、整理目标目录和移动既有
文献不属于 P8。

## 哈希、去重与重导

### 哈希

PDF SHA-256 在后台以有界缓冲流式计算，不把整个文件载入内存。扫描记录开始与结束时的文件
大小、修改时间和文件身份；任一发生变化时，该项目标记为“扫描期间变化”，不得用不一致的
哈希发布。

Zotero 复制完成后对目标文件重新计算 SHA-256，必须与来源相同才进入候选快照。哈希不进入
日志、遥测或网络，只保存在本地文献记录用于去重和诊断。

### 判定优先级

1. 同一 Zotero library 与 attachment key：视为同一来源附件；
2. 现有 `FileIdentity` 判定为同一文件：复用现有记录；
3. 完整 SHA-256 相同：提示为相同内容并默认复用现有记录；
4. 仅 DOI、标题、作者或文件名相同：不自动合并。

不同来源但哈希相同的 PDF 复用同一 `PaperRecord`，只在用户确认后补充导入文献集归属和非冲突
来源信息。一个记录不保存相互矛盾的两个主来源；额外来源作为去重别名保存。

### 再次导入

- 同一 Zotero 附件且哈希未变：不再次复制，只补充缺失归属和用户确认的非手动元数据。
- 同一附件内容变化：标记“新版本冲突”；默认保留现有记录和文件，用户可以另存为新文献。
- 不提供静默替换，因为页数和版面变化可能使既有高亮、笔记和阅读位置失效。
- 同一文件夹来源新增 PDF：新增对应记录和必要分类。
- 外部来源删除 PDF、文献或文献集：不从 Lurume 删除任何内容。
- 外部改名或移动分类：显示结构差异，由用户决定是否应用；Lurume 中手动改名或移动的节点
  默认保留。
- 同名但来源不同的文献集默认创建编号名称；用户可以在预览中明确合并到现有目标。

## 导入事务

导入协调器使用独立 request ID 和以下状态：

```text
空闲
→ 扫描来源
→ 计算哈希与读取元数据
→ 等待预览确认
→ 准备事务
→ 复制与校验
→ 构造候选快照
→ 原子发布
→ 完成 / 已取消 / 失败
```

新导入、关闭向导或用户取消都会使旧 request ID 失效。异步扫描、XPC 分页、哈希和复制的迟到
事件只能清理自身资源，不能更新新向导或文献库。

### 扫描与预览

- 扫描阶段只读，不创建文献集、不复制文件、不修改现有记录。
- 工作在有界并发队列中，不能为每个 PDF 同时创建任务或文件句柄。
- 预览包含将创建的层级、文献数量、复制总字节、复用、冲突、无效 PDF、缺失附件、未授权
  路径和未支持 Zotero 数据。
- 用户可以排除单项、整个目录或文献集，也可以对同类冲突批量应用相同决定。
- 预览中的绝对路径默认折叠，只显示用户选择根下的相对路径；展开诊断时仍只在本机展示。

### 执行与发布

Zotero 文件先复制到目标卷内的专用暂存目录，例如：

```text
.lurume-import-staging/<transaction UUID>/
```

事务日志只保存在 Lurume Application Support，记录事务 ID、用户已确认的目标、由本事务创建的
暂存/最终路径和阶段，不记录 Zotero 密钥或 PDF 内容。

单个项目读取失败、无权限或校验失败时从有效候选集中排除并进入报告，其他有效项目继续。
全部有效项目的书签、哈希、复制和候选层级准备完成后才进入最终发布：

1. 把已校验暂存文件原子移动到不冲突的最终名称；
2. 为最终 URL 创建安全作用域书签和文件身份；
3. 原子保存完整候选 `LibrarySnapshot`；
4. 保存成功后发布内存状态并删除事务日志。

任一步失败都必须恢复旧文献库，并只清理该事务创建、尚未被成功文献库引用的文件。不能删除
目标目录中导入前已存在的同名文件。应用崩溃后，下次启动读取事务日志：已发布且可由当前
快照证明引用的文件保留；未发布的暂存或已标记新建文件清理；无法证明归属时停止自动清理并
给出诊断，宁可留下孤立副本也不误删用户文件。

用户在最终发布前取消时，文献库保持原样并清理本次暂存副本。第一版不保留“已经完成的一
部分”。发布后的整个批次可以注册为一个应用级撤销动作；撤销只移除本批次创建的文献记录、
层级和归属，不删除已复制到用户目录的 PDF，这一点在执行确认和撤销名称中明确说明。

## 元数据编辑与搜索

文献库表格继续显示状态、标题、作者摘要和年份。P8 不增加可配置列、水平滚动列组或按 DOI、
期刊、文献类型排序。

Return、右键“编辑信息”或详情入口打开分区式编辑器：

- 基本信息：类型、标题、日期；
- 创作者：可增删、排序、选择角色，支持个人姓名和机构名；
- 出版信息：容器标题、卷、期、页码、出版社、出版地和版本；
- 标识符与链接：DOI、ISBN、ISSN、arXiv、URL；
- 其他：语言、摘要、附件标签和只读来源摘要。

保存前完成字段级校验；无效 DOI、URL 或年份不覆盖已保存值。清空字段是有效手动决定。
编辑器不显示 Zotero 绝对路径、server ID 或内部 key，诊断信息通过单独的可复制报告提供。

普通文献库搜索扩展到标题、创作者、年份、容器标题、DOI、ISBN、ISSN、arXiv 和 URL。摘要
默认不参与普通搜索；P8 不增加 PDF 正文、摘要全文、模糊相似度或语义搜索。递归文献集筛选
先得到去重论文 ID，再应用搜索、阅读状态和现有排序，不能因为多重归属显示重复行。

## 错误与报告

错误至少区分：

- Zotero 未运行；
- Zotero Local API 未开启或返回 `403`；
- API 版本或 schema 不受支持；
- localhost origin 或重定向违规；
- JSON 不完整、超限或分页不一致；
- 文件不存在、未下载、不是 PDF、没有权限或扫描期间变化；
- 目标空间不足、重名、复制失败、哈希不一致或书签创建失败；
- 元数据字段无效或无法映射；
- 文献集循环、同级名称冲突或来源匹配冲突；
- 事务取消、恢复失败或文献库原子保存失败。

失败不触发云 API、SQLite 读取、自动重试、静默覆盖或自动删除。网络请求不自动重试；用户在
预览或结果页明确点击“重新扫描”才产生新请求。

结果报告按新增、复用、跳过、冲突、失败和未支持数据分类。默认只保留当前会话；用户可以
主动导出 UTF-8 文本报告。报告不包含 PDF 正文、Zotero 响应原文、API 凭据或完整绝对路径；
文件以相对路径、附件标题和本地错误类别表示。

## 隐私与安全

- 文件夹扫描和 Zotero 迁移都只在用户明确操作后开始。
- Zotero metadata 与标题会在专用 XPC 和主 App 之间传递，但不会发送到互联网或翻译服务。
- Zotero 本地读取不需要也不保存 zotero.org API Key。
- 任何日志使用数量、request ID 和错误类别；标题、作者、DOI、URL、路径和响应正文默认隐私
  遮蔽。
- XPC 协议只接受允许类集合，限制数组数量、字符串长度和总归档大小。
- XPC 失效、崩溃或签名校验失败只使本次 Zotero 扫描失败，普通文件夹导入和现有文献库保持
  可用。
- API 返回的 `file:` URL 不获得特殊信任；规范化后必须位于用户授权根目录内。
- 目标写权限只来自系统选择器和安全作用域书签，不扫描常见 Zotero 路径或用户主目录猜测权限。
- 发布产物和测试夹具不得包含真实 Zotero 标题、文件路径、server ID、文献 key 或用户 PDF。

## 并发、取消与性能

- 目录枚举、XPC 请求、JSON 解码、PDF 校验、哈希和复制都不在主线程执行。
- UI 状态更新通过明确隔离边界回到主 actor；Swift 6 strict concurrency 保持开启。
- Zotero API 按官方分页读取，单页和总项目数均设置资源上限；大文库不一次性解码成无界对象图。
- 哈希和复制采用固定大小缓冲并限制并发文件数；不能按文献数量线性增加内存。
- 复制进度按已验证字节而不是文件数量展示，避免一个大 PDF 看似卡住。
- 取消必须停止新分页、目录枚举和文件任务，关闭句柄，并让 XPC 请求失效。
- 父文献集递归成员计算使用预构建的无环索引，不能为每一行重复遍历整棵树。
- 搜索和计数继续在内存记录上完成，不为表格每一行同步访问 PDF、书签或 Zotero。
- 无导入时不保留扫描任务、文件句柄、Zotero XPC connection 或持续 CPU 活动。

性能验收至少包含：

- 一个含 50 个 PDF、三层目录的固定文件夹；
- 一个约 1,000 篇文献、100 个嵌套文献集和多重归属的合成 Zotero fixture；
- 多个重复文件、同名文件、缺失附件、无权限目录、扫描期间变化文件和多 PDF 条目；
- 一次包含大 PDF 的复制、取消、重启恢复和再次导入；
- 导入前、扫描中、复制中、完成后和取消后的 App/XPC RSS、CPU、句柄与临时文件变化；
- 文献集展开、父级递归计数、搜索和列表滚动的三次样本与中位数。

P8 不在实现前虚构绝对耗时或内存上限，但不得出现主线程长时间阻塞、任务/句柄随文献数无界
累积、取消后继续复制、重复 XPC 进程累积或未完成暂存目录长期增长。

## 与 P0–P7 的兼容性

- 现有单个/多个 PDF 导入、文件身份判重、安全书签、改名恢复和手动重新定位继续有效。
- v1–v4 文献库升级后论文 ID 不变，因此高亮、笔记和选择关系继续归属于原论文。
- 阅读位置、阅读状态、添加时间、最近打开时间和当前选择在 v5 迁移中原样保留。
- 嵌套文献集只改变组织查询；PDF 阅读侧栏、目录、缩略图和检查器不改为树形文献库。
- 文献集递归删除不调用现有整库移除论文协调器，不删除高亮或笔记。
- P7 翻译缓存键、请求代次、API 配置和 Translation XPC 不读取新增引用元数据；翻译仍只发送
  当前选中文字。
- P6 更新检查、发布签名和 Sparkle XPC 不读取导入目录或 Zotero 数据。
- 现有表格列、阅读状态筛选和排序行为不因新增字段改变默认值。
- 无法安全迁移 v4、检测到文献集循环或事务日志不一致时，沿用现有只读保护，不覆盖原库。

## 不纳入 P8 第一版

- 文件夹监控、自动导入、镜像删除或双向同步
- Zotero 云 API、账户登录、OAuth、API Key 或 WebDAV 下载
- 直接读取或修改 `zotero.sqlite`
- 向 Zotero 写回文献、文献集、附件、标签或笔记
- Zotero 标签、笔记、批注、关系、保存搜索、全文索引和文字处理器 citation links
- 网页快照、EPUB、图片、音视频、数据集和其他非 PDF 附件
- 一条 Lurume 文献包含多个 PDF 的附件切换模型
- OCR、PDF 正文解析、语义查重和根据标题/DOI 自动合并
- BibTeX、BibLaTeX、RIS、CSL-JSON 导入导出和格式化引用
- Crossref、DOI、arXiv 或其他联网元数据补全
- 自动删除、移动、重命名或整理用户 PDF
- 未引用文件清理器、应用内文件管理器和受管理废纸篓
- 文献表格可配置列、按新增元数据排序和摘要/全文搜索
- 手动文献集排序、智能文献集、标签系统和递归删除论文内容

## 测试策略

### 纯模型与迁移测试

- v1、v2、v3、v4 到 v5 的逐字段无损迁移；
- v5 只有一个持久化标题，兼容访问器、内联改名和详细编辑器不会产生分叉副本；
- legacy 作者字符串不被错误拆分；
- 父节点缺失、自环、多节点循环、同级重名和跨级同名；
- 递归成员去重、计数、搜索与“未分类”语义；
- 移动文献集的循环拒绝；
- 递归删除和撤销恢复完整子树与多重归属；
- Zotero 字段到通用元数据的固定映射、未知角色和无效日期；
- 手动覆盖、手动清空和重导差异；
- 来源 ID、文件身份与 SHA-256 的判定优先级。

### 文件夹导入测试

- 多层目录、根目录 PDF、空目录、隐藏文件、package、符号链接和 Finder 替身；
- PDF 属性标题判废、文件名回退、literal author 和预览后不再二次自动改写；
- 假 PDF、损坏 PDF、无权限、扫描期间删除或变化；
- 当前目标父文献集、同名冲突、合并选择和重复导入；
- 扫描取消、过期事件、整批提交失败与原 PDF 哈希不变；
- 大目录有界并发、句柄释放和主线程响应。

### Zotero Core 与 XPC 测试

测试服务只监听 `127.0.0.1`，使用完全合成的文库、collection、item 和附件路径。覆盖：

- API 探测、版本 header、个人/群组文库和分页；
- Zotero 10.x 基线、Local API v3 capability probe、未经验证主版本和缺失端点拒绝；
- 单 PDF、多 PDF、独立 PDF、无 PDF、未下载和非 PDF；
- 多重归属、嵌套 collection、未知 item type/creator role；
- `403`、超时、截断 JSON、超限响应、分页变化和取消；
- 同 origin 有限重定向与跨 origin/端口/scheme 跟随前拒绝；
- XPC 连接方签名、允许类、失效事件、并发请求和最后请求后 connection 释放；
- 服务无文件/Keychain 权限，主 App 无通用网络权限。

### 复制与事务测试

- 来源与目标哈希一致、扫描期间变化和复制后篡改；
- 目标重名、磁盘空间不足、写入失败、书签失败和原子快照失败；
- 目标等于、包含或位于任一 Zotero 来源根内时拒绝，新增外部来源授权后重新校验；
- 取消时只清理本事务暂存文件；
- 崩溃恢复区分已发布、未发布和无法证明归属的文件；
- 既有目标文件、Zotero 原文件和文件夹原文件绝不被覆盖或删除；
- 重导未变附件、变化附件、相同哈希不同来源和仅元数据相似的不同 PDF。

### 回归与真实验收

- P0–P7 全量自动化继续通过；
- 真实 Finder 文件夹导入至少覆盖三层分类和 50 个 PDF；
- 在用户明确授权后，用不含敏感材料的隔离 Zotero fixture 或专用测试文库完成真实本地 API
  迁移；不得擅自迁移用户日常 Zotero 文库；
- 真实验收前后比较来源 PDF 哈希、Zotero 数据和目标目录；
- 测试取消、重启恢复、重导、递归删除与撤销；
- Release 构建、严格签名、Universal 架构、DMG 挂载和两个内嵌专用 XPC 复检。

## 发布与打包边界

P8 新增 XPC 并改变主 App 文件 entitlement，必须扩展 P6 发布工具：

- Release App 和挂载 DMG 中必须恰好包含 Translation XPC 与 Zotero Import XPC 各一份；
- 两个 XPC 的 Bundle ID、包类型、最低系统版本、架构和签名分别固定；
- Translation XPC 保持网络 client 且无文件权限；
- Zotero Import XPC 保持网络 client 且无文件权限、Keychain 或写服务能力；
- 主 App 允许 user-selected read-write，但仍禁止 generic network client 和调试 entitlement；
- `project.yml` 与生成的 `Lurume.entitlements` 必须把现有 user-selected read-only 替换为
  read-write；`prepare-release` 新增主 App 必须具有 read-write、不得残留 read-only 或其他广泛
  文件 entitlement 的正向与反向断言；
- 现有 P6 脚本中用 read-only fixture 验证 Translation XPC 拒绝任意文件权限的测试必须保留；
  它不是主 App entitlement 断言，不能在改造时误删或改成允许 XPC 文件访问；
- 生产二进制不得包含 fixture 标题、固定 Zotero item key、固定测试目录或用户路径；
- 发布预检不启动 Zotero、不扫描文件、不读取导入目标，也不产生真实迁移；
- 记录新增 XPC、元数据模型和导入 UI 对 App/DMG、冷启动、无导入空闲内存与进程的增量。

## 分阶段检查点

### 检查点一：模型、迁移与纯导入规划器

- 实现 v5 引用元数据、来源标识、哈希字段和嵌套文献集模型；
- 完成 v1–v4 无损迁移、无环校验、递归成员与删除候选算法；
- 实现不接触 UI/网络/真实文件的文件夹树和 Zotero DTO 映射规划器；
- 用固定 JSON 和合成目录描述锁定去重、冲突和差异规则；
- 全量回归通过后暂停，不改变现有导入界面，不新增 XPC。

### 检查点二：嵌套文献集与元数据体验

- 来源栏树、创建子集、拖放移动、移到顶层、递归展示、计数和递归删除；
- 完整撤销、焦点、键盘和辅助功能；
- 分区元数据编辑器、结构化创作者和扩展普通搜索；
- 旧文献真实迁移与人工回归；
- 通过后暂停，不扫描目录、不连接 Zotero。

### 检查点三：文件夹批量导入

- 目录选择、后台扫描、PDF 验证、哈希、层级映射和来源重导；

- 文件夹原位书签、原文件哈希保护和大型目录性能；

### 检查点四：Zotero Local API 与专用 XPC

- 主 App 只展示来源、映射预览和权限需求，不复制或提交真实 Zotero PDF；
- 通过后暂停，等待检查点五真实文件授权。

### 检查点五：复制事务、发布加固与真实验收

- 清理测试记录和临时文件后，才决定 P8 是否最终通过。

## P8 验收标准

P8 第一版至少同时满足：

1. v1–v4 文献库可以无损升级到 v5，论文、文献集、页码、状态、高亮和笔记归属不变。
2. 文献集可以任意嵌套，父引用有效、无环，同级名称唯一且跨父级可以同名。
3. 父文献集递归显示后代论文并按 ID 去重；“未分类”只包含零归属论文。
4. 文献集可以创建子级、移动、移到顶层和撤销，循环移动在修改前被拒绝。
5. 删除文献集递归删除完整子树和归属，但不删除论文、PDF、高亮、笔记或阅读位置；撤销完整恢复。
6. v5 只有一个持久化书目标题；内联改名、详细编辑、导入和回退显示不会产生分叉副本；扩展元数据能够保存、编辑、搜索和往返编码，legacy 作者不因猜测解析而损坏。
7. 手动编辑和清空字段在 PDF 属性读取及 Zotero 重导后保持优先。
8. 文件夹扫描只访问用户选择根，跳过隐藏项、package、符号链接和替身，不越过授权边界。
9. 根目录和子目录准确映射为嵌套文献集，空目录不创建，PDF 只直接归属所在节点；初始标题按可信 PDF 属性再文件名回退，作者按 literal 候选处理，确认后不再二次自动改写。
10. 文件夹导入原位引用，导入、重导、分类和删除前后原 PDF 哈希不变。
11. Zotero Import XPC 只访问固定 `127.0.0.1:23119/api/` 且只实现读方法，跨 origin 重定向在跟随前拒绝。
12. 主 App 没有通用网络权限；Zotero XPC 没有文件、Keychain、server 或调试权限。
13. Zotero 10.x 与 Local API v3 capability probe 通过；未运行、API 未开启、缺少必需端点或版本未经验证时给出明确说明，不读取 SQLite 或切到云 API。
14. 个人与可见群组文库、嵌套 collection、多重归属和选择范围映射正确。
15. 一个 PDF 生成一条记录；多 PDF 条目生成多条记录；无 PDF、未下载和非 PDF 项准确报告。
16. Zotero 父条目元数据优先且附件标签不覆盖书目标题；未知字段不污染通用 schema。
17. 来源文件和目标目录都经过系统明确授权，API 文件 URL 不能绕过授权根校验；目标与任一 Zotero 来源根在两个方向上都不得重叠。
18. Zotero PDF 先暂存、复制并双端校验哈希，再进入候选快照；绝不覆盖既有目标文件。
19. 同来源、同文件身份和同 SHA-256 的重复项按规则复用；仅元数据相似不会静默合并。
20. 变化附件不会覆盖可能已有批注的 PDF，只能保留或由用户明确另存为新文献。
21. 重导只增量增加或应用确认的变化，不传播外部删除、改名或移动。
22. 扫描和预览阶段不修改数据；取消或最终保存失败不留下半套文献库或未证明归属的暂存文件。
23. 崩溃恢复只清理由本事务明确创建的未发布文件；无法证明时停止而不是猜测删除。
24. 从 Lurume 移除记录或文献集不会删除文件夹原文件或 Zotero 复制目标。
25. 导入期间既有阅读、搜索、翻译、高亮、笔记和文献库操作保持响应。
26. 大目录和 1,000 项 Zotero fixture 下分页、哈希、复制、递归计数和搜索保持有界内存与句柄。
27. 取消后不继续产生网络请求、哈希或复制，最后请求结束后 XPC connection 释放。
28. 报告准确区分新增、复用、跳过、冲突、失败和未支持内容，不泄漏响应正文或完整绝对路径。
29. P0–P7 自动化无回归，Release、严格签名、Universal 架构、DMG 和双 XPC 校验通过。
30. 真实验收只使用用户明确授权的文件夹和隔离 Zotero 文库；结束后清理测试记录与临时文件。
