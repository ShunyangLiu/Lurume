# Lurume P0 原型规格

状态：已确认
更新日期：2026-08-26

## 目标

P0 用一条最小但真实的纵向链路验证 Lurume 的核心体验：用户无需把文件交给应用，便能在一个原生 macOS 窗口中阅读本地 PDF，并获得不会阻塞阅读的划词翻译。

```text
导入本地 PDF
→ 在文献列表中打开
→ 使用内置阅读器阅读
→ 选择文字后自动翻译
→ 重启后恢复文献和阅读位置
```

P0 是技术与交互原型，不是可公开发布的最小产品。判断其成功的关键不是功能数量，而是这条链路是否稳定、顺畅并值得继续扩展。

## 已确定的产品边界

- 最低系统版本为 macOS 15。
- P0 只有一个主窗口，通过文献列表切换当前 PDF。
- 应用引用用户选择的原始 PDF，不复制、不移动、不修改文件。
- 阅读器使用系统 PDF 能力，支持基础阅读、缩放、搜索、导航和文字选择。
- 选择文字后自动翻译；用户可以在设置中关闭自动翻译。
- 自动识别原文语言，默认目标语言为简体中文。
- 翻译和文件恢复等耗时或失败操作不得阻塞 PDF 阅读。
- 清除 PDF 选区后，最后一次翻译继续保留。
- 多窗口和标签页不属于 P0。

## 界面模型

主窗口由文献列表、PDF 阅读区和可显示或隐藏的翻译检查器组成。

```text
文献列表                 PDF 阅读区                翻译检查器
────────────            ─────────────────         ────────────
文件名                   PDF 正文                  原文
最近阅读时间             阅读工具                  译文
文件状态                 搜索与页码                文献名与页码
                                                  状态与操作
```

P0 不为只有一个入口的文献列表额外增加项目或标签侧边栏。后续加入收件箱、项目和标签时，再扩展为完整的三栏文献库布局。

## PDF 导入与文件所有权

用户可以通过文件选择器或把 PDF 拖入主窗口来导入文献。

- 导入只创建文件引用和最小本地记录，不创建 PDF 副本。
- 同一文件重复导入时，应用定位并打开已有记录，不创建重复文献。
- 从文献库移除条目时，只删除应用内引用，不删除原始 PDF。
- 应用重启后应能通过安全作用域书签重新访问原文件。
- 文件在同一卷内被移动或重命名时，优先尝试自动恢复引用。
- 无法恢复时，列表显示“文件不可用”，并提供“重新定位”操作。
- 用户取消重新定位后，其他文献和阅读功能继续可用。

P0 对“同一文件”的定义如下：

- 优先使用卷标识与 `documentIdentifierKey` 的组合判断文件身份；
- 文件系统不支持持久文档标识时，退回到安全作用域书签解析后的标准化文件 URL；
- 安全作用域书签用于恢复访问权限，不直接作为相等键；
- 同卷移动或重命名通常仍视为同一文件；
- 跨卷复制产生的文件视为另一份文献；
- 不计算内容哈希，也不识别内容相同但文件身份不同的副本。

书签与文件标识恢复均按“最佳努力”处理，不能假设所有卷和文件提供商具有相同行为。跨卷移动或无法解析书签时进入手动重新定位流程。

P0 的文献记录只需要包含应用内稳定标识、卷与文档标识、访问书签、显示名称、导入时间、最后打开时间和最后阅读页码。标题、作者、DOI、期刊和年份等学术元数据不在本阶段解析。

## 阅读行为

- 打开文献后显示嵌入式原生 PDF 阅读器。
- 支持连续滚动、缩放、页码导航、文内搜索和文字选择。
- 在文献之间切换时，分别保存并恢复最后阅读页码。
- 关闭并重新启动应用后，恢复文献列表和上次阅读位置。
- 密码保护、损坏或无法解析的 PDF 应显示局部错误，不导致应用退出。
- P0 不写入标准 PDF 批注，也不修改原文件。

## 自动翻译行为

### 触发

- 自动翻译默认开启。
- 选区稳定约 250 毫秒后发起翻译，避免拖动选区过程中重复请求。
- 鼠标、触控板或键盘造成的文字选区使用相同行为。
- 纯空白选区不触发翻译。
- 使用 `NLLanguageRecognizer` 从当前 PDF 页面的正文样本识别源语言，再把结果明确传入 `TranslationSession.Configuration`；目标语言默认为简体中文。
- 页面上下文只用于语言识别，实际送入翻译的内容仍严格限于用户选区，因此单词、缩写和术语不依赖自身长度完成语言判断。
- 无法识别源语言，或语言组合不受支持时进入明确的错误状态，不静默跳过翻译。
- 保留 PDFKit 提取的原始文本用于显示和复制，并生成单独的规范化文本作为翻译输入。
- 规范化可以清理多余空白和明显的换行噪声，同时尽量保留真实段落。
- 连字、分栏、数学公式和行尾连字符只能启发式处理，不承诺完美还原原文。

### 并发与取消

- 新选区出现时立即取消应用持有的旧 Swift 任务。
- 每次请求具有递增代次标识；旧任务即使稍后返回，也不得覆盖新选区的结果。
- macOS 15 实现不得依赖仅在更高系统版本可用的显式 `TranslationSession.cancel()`。
- 在翻译加载、语言资源下载、失败或重试期间，用户仍能滚动、缩放、搜索和切换文献。
- P0 可以缓存当前会话中的重复翻译；持久化翻译缓存不属于本阶段。

### 翻译检查器

产生有效选区时自动显示右侧翻译检查器。检查器至少具有以下状态：

- 等待翻译
- 正在翻译
- 翻译成功
- 语言资源尚未就绪
- 翻译失败
- 任务已取消

成功结果显示原文、译文、文献名称和页码，并提供复制原文、复制译文和清空操作。

语言资源尚未安装时，下载许可、下载进度和必要的语言选择由 Translation framework 的系统界面负责。Lurume 只展示外围的准备状态，不复制、遮挡或替代系统 sheet。系统界面被关闭后，系统仍可在后台继续下载，Lurume 同时保持 PDF 阅读可用。

清除 PDF 选区不会清空翻译检查器。最后一次结果一直保留到以下任一事件发生：

- 用户选择新的文字；
- 用户主动清空；
- 当前文献从文献库移除。

关闭检查器只隐藏界面，不改变“自动翻译”设置。自动翻译开启时，下一个有效选区会再次显示检查器。

### 设置与手动模式

“设置 → 翻译”至少包含：

- 自动翻译选中文字，默认开启；
- 目标语言，默认简体中文。

~~翻译检查器菜单提供自动翻译的快捷开关。~~ 该入口已由后续阶段调整：自动翻译开关移入标准“设置 → 翻译”窗口，翻译检查器菜单不再提供快捷开关。关闭自动翻译后，选区仍会进入检查器，但必须由用户点击“翻译”、选择菜单命令或按 `⇧⌘T` 才发起任务。该快捷键只翻译当前有效选区；没有有效选区时不执行操作。

## 技术约束

- 使用 Swift 6 和原生 Apple 框架。
- SwiftUI 负责应用外壳，PDFKit 的 AppKit 视图负责 PDF 交互。
- 使用 Apple Translation framework 完成 P0 翻译，并检查语言组合及本地资源状态。
- Translation framework 的 P0 基础能力以 macOS 15 为部署目标；不得无保护地调用更高系统版本才提供的 API。
- 翻译实现必须有可替换边界，以便测试取消、失败和乱序返回；P0 不接入第三方翻译服务。
- 开启 App Sandbox，使用安全作用域书签持久化文件访问权限。
- P0 只建立一个 macOS App target，不提前创建 iOS target 或大型模块体系。
- 文献记录保存在应用 Application Support 目录中的单个版本化 JSON 文件内。
- JSON 顶层包含格式版本；书签 `Data` 由系统编码器编码，写入采用原子替换。
- 阅读页码变更采用短暂防抖，并在切换文献、关闭窗口时及时刷新，避免滚动期间频繁写盘。
- P0 不承诺存储格式稳定，也不实现原型版本之间的数据迁移。
- 完整数据库与开放 sidecar 格式在数据模型稳定后决定。

## 不在 P0 中实现

- DOI、arXiv、Crossref 或其他在线元数据识别
- 项目、标签、智能文件夹和文献查重
- 全文索引、OCR 和系统 Spotlight 集成
- PDF 高亮、批注写入和摘录笔记
- Markdown、BibTeX、RIS 和 CSL-JSON 导入导出
- 持久化翻译历史和第三方翻译服务
- iCloud 同步、账户和自建云服务
- 多窗口、标签页、iPadOS 和 iOS 应用
- 插件系统、自动化接口和写作引用插件

## 验收标准

P0 只有同时满足以下条件才算完成：

1. 可以通过选择器和拖放导入多个本地 PDF。
2. 重复导入同一文件不会产生重复记录。
3. 应用不复制或修改用户的原始 PDF。
4. 可以稳定完成滚动、缩放、搜索、导航和文字选择。
5. 每篇文献分别恢复最后阅读页码，重启应用后记录仍然存在。
6. 有效选区稳定后自动翻译，并在检查器显示原文、译文、文献名和页码。
7. 快速连续改变选区时，旧任务被取消，旧结果不会覆盖新结果。
8. 清除选区后最后一次译文仍然可见、可复制和可清空。
9. 关闭自动翻译后不再自动发起任务，但按钮、菜单和 `⇧⌘T` 手动翻译仍可使用。
10. 翻译失败、语言资源不可用或文件失效时，PDF 阅读保持响应。
11. 文件在同卷移动后能够自动恢复；跨卷移动或恢复失败时允许用户重新定位。
12. 损坏、受密码保护或不可访问的 PDF 不导致应用崩溃。

### 性能基线方法

性能验收使用 Release 构建和固定样本集。每次记录以下环境信息：Mac 型号、芯片、内存、macOS 版本、Xcode 版本和应用构建标识。

固定样本集至少包含：

- 一份 20～50 页、可正常选择文本的普通论文；
- 一份 300 页以上的可搜索大型 PDF；
- 一份以扫描图像为主、没有可选择文本的 PDF；
- 一份受密码保护的 PDF；
- 一份损坏或截断的 PDF。

样本记录文件名、字节大小、页数和 SHA-256，保证后续测量使用相同文件。至少测量：

- 应用启动到主窗口可交互的耗时；
- 选择文献到首个 PDF 页面可见的耗时；
- 主窗口空闲 30 秒后的内存；
- 连续阅读大型 PDF 10 分钟后的内存及其变化。

每个时间指标在同一构建下测量三次并报告中位数。首次启动或首次语言包下载等一次性成本单独记录，不与普通启动或翻译耗时混合。P0 先建立可信基线，不在实现前设置脱离实测的硬性性能数字。

## P0 之后

完成 P0 后先进行一次真实论文阅读评审，再决定 P1。预期的下一条纵向能力是 PDF 学术元数据识别与可整理的文献库，而不是直接扩展多平台、同步或插件系统。
