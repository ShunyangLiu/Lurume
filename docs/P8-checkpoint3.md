# P8 检查点三：文件夹批量导入

日期：2026-08-31

结论：**通过。按计划停在检查点三，不进入 Zotero Local API、Zotero Import XPC、目标目录或复制事务。**

## 本检查点完成内容

- “文件”菜单、阅读侧栏和文献库工具栏新增“导入文件夹…”入口。目录选择器只允许选择一个
  文件夹；当前用户文献集会作为导入根文献集的默认父级，顶层位置也可在预览中重新选择。
- 扫描器只在明确用户手势后启动，在后台递归枚举授权根；跳过隐藏项、macOS package、符号
  链接和 Finder 替身，不跟随越过根目录或形成循环的引用。扫描有 100,000 项安全上限，PDF
  处理和最终校验的并发上限均为 4。
- 第一版只候选化 `.pdf` 文件；每个候选必须有 `%PDF-` 文件头和末尾 `%%EOF` 标记。SHA-256
  使用 1 MiB 有界缓冲流式计算，不把整份 PDF 读入内存。扫描前后重新获取文件身份、字节数和
  修改时间；任一变化都会拒绝该候选。
- PDF 属性标题继续使用 `PaperTitleRules` 判废，失败时回退文件名；作者作为一个 literal author
  候选。属性读取失败不阻止有效 PDF 导入，也不会在确认后再触发第二次异步覆盖。
- 根目录和非空子目录映射为嵌套文献集；空分支剪除，PDF 只直接归属所在目录。已记录的目录
  来源优先复用，手动改名、移动和手动元数据继续受保护。
- 同名目标默认生成稳定编号名称，用户可明确合并到同级同名目标。来源、文件身份和 SHA-256
  依次去重；仅元数据相似不会合并。同来源内容变化默认保留现有记录，用户可逐项或批量选择
  另建记录。
- 预览可排除单个 PDF 或整个目录，显示新增、复用、版本冲突、容量、元数据更新/手动字段保护、
  无效 PDF 和跳过项。报告区分新增、复用、跳过、冲突和失败，只记录相对路径，不写完整来源
  路径或系统错误正文。
- 确认时对全部包含项再次流式哈希和校验，然后为新增记录创建逐文件只读安全作用域书签。根
  目录的只读书签只保存在根来源记录，不参与来源相等性或哈希，也不会重复写入每篇论文。
- 候选论文、文献集、归属、来源别名和元数据在持久化成功后一次发布；保存失败不发布任何一
  部分。整个批次注册为一个“文件夹导入”撤销动作。
- 扫描和执行均有独立 request ID。新导入、关闭或取消会使旧请求失效；迟到进度和结果不能
  更新新向导或文献库。取消停止调度新项目，并让当前有界文件操作完成清理。
- 既有“导入 PDF”界面入口现在复用相同的最低 PDF 验证、流式哈希、候选元数据、文件身份/
  SHA-256 去重和原子发布核心，不强制进入文件夹向导。

## 原位引用与性能证据

- 端到端临时目录回归执行了：真实 PDF 字节写入 → 递归扫描 → 预览 → 二次哈希 → 逐文件书签
  → 候选快照 → 持久化 → 单步撤销。导入前后两个原文件的字节和 SHA-256 完全相同。
- 50 个 PDF、3 层目录的真实文件系统 fixture 在并发上限 4 下完成；测试锁定最大元数据并发
  不超过 4，并设置 10 秒保守上限。当前机器样本约 0.31 秒；该数值只用于发现明显退化，不是
  跨设备性能承诺。
- 根符号链接、隐藏 PDF、package 内 PDF、越界引用、无效 PDF、扫描中变化、预览后变化、项目
  数上限、书签和保存失败均有自动化边界。
- 原位引用不会制作历史副本：如果用户或其他程序以后在 Finder 中覆盖同一原文件，Lurume 也
  会读到新内容。向导明确展示这一点；Lurume 自身不会复制、移动、重命名、覆盖或删除原文件。
