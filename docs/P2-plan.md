# Lurume P2 高亮阅读计划

状态：已确认，已完成实现前审查
更新日期：2026-08-27

## P2 目标

P2 让 Lurume 从“可以阅读和翻译论文”进入“可以在阅读过程中留下并重新找到重点”的阶段。核心能力是由 Lurume 独立保存的 PDF 文字高亮，而不是摘录卡片、笔记系统或对原 PDF 的批注写回。

```text
选择论文文字并查看翻译
→ 添加黄色高亮
→ 高亮跨重启保留
→ 从当前论文的高亮列表重新定位
→ 点击页面高亮时按当前设置重新翻译
```

P2 成功的关键是：添加高亮足够轻，不打断现有划词翻译；保存可靠且不修改用户文件；几十页后仍能从列表找到已经标记的位置。

## 已确认的产品边界

- 高亮属于 Lurume，只保存在应用本地，不写入或修改原 PDF。
- P2 只提供一种黄色高亮，不提供颜色选择或颜色语义。
- 高亮只基于 PDFKit 能够选择的文字；没有文本层的扫描 PDF 不在 P2 中加入 OCR 高亮。
- 一次用户操作产生一条逻辑高亮，多行和跨页选区均可包含在同一条记录中。
- 高亮保存原文和页面位置，不保存当时的译文；重新访问时按照当前翻译设置再次翻译。
- 右侧检查器在“翻译”和“高亮”两种内容之间切换，不增加新的常驻栏。
- 高亮列表只显示当前论文，不提供跨文献汇总。
- 现有 PDF 搜索、阅读位置、文献元数据和翻译行为继续保持。

## 添加高亮

### 入口

用户先在 PDF 中选择有效文字，然后通过以下任一入口添加高亮：

- 按 `⇧⌘H`；
- 在 PDF 选区的右键菜单中选择“添加高亮”。

没有有效用户选区、选区只有空白、选区无法解析出页面位置或当前文献不可写入高亮存储时，命令不可用或不执行，不创建空记录。

### 添加后的状态

高亮成功保存后：

- 蓝色文字选区自动清除；
- 页面上立即显示黄色高亮；
- 右侧继续保留刚才的译文、文献名和页码；
- 检查器继续停留在“翻译”，不自动切换到高亮列表；
- 清除选区或继续滚动不会移除黄色高亮。

只有在本地高亮数据成功落盘后，操作才算完成。保存失败时页面不得留下看似成功但重启即消失的高亮；应用应回退本次界面变化并给出明确、非阻塞的错误提示。

## 高亮范围与显示

- 使用 PDFKit 选区的逐行位置生成高亮，而不是用一个大矩形覆盖整段，避免遮住双栏之间或段落空白处的无关内容。
- 位置以 PDF 页面坐标保存，不依赖当前缩放比例或窗口尺寸。
- 多行选区保存为同一条记录中的多个位置片段。
- 跨页选区保存为一条逻辑记录，内部按页面保存多个片段；列表只显示一项。
- 黄色应足以识别，同时保持正文可读；当前被重新选中的高亮使用系统蓝色文字选区，清除选区后恢复为黄色。
- 页面旋转、裁切框和缩放变化不得改变高亮与原文字的相对位置。
- 原 PDF 自带的标准批注继续由 PDFKit 正常显示，但不自动导入为 Lurume 高亮，也不与 Lurume 高亮混淆。

## 重复与重叠规则

- 对尚未高亮的用户选区执行添加命令时，创建新高亮。
- 对范围基本相同的已有高亮再次按 `⇧⌘H`，删除该高亮，形成可预测的开关行为。
- 相同范围不会产生两条重复记录。判定以同一文献、相同页面片段及带容差的位置比较为准，不能只比较原文字符串。
- 新选区只与旧高亮部分重叠时，两条记录独立保留，不自动合并、拆分或扩大范围。
- 重叠区域可能显示得稍深；P2 接受这一结果，不擅自改变用户的原始选择。

## 页面高亮交互

- 单击 Lurume 创建的黄色高亮时，重新选中该高亮的原文并滚动到可视区域中央。
- 检查器切换到“翻译”；自动翻译开启时按现有防抖和取消规则发起翻译，关闭时进入可手动翻译的选区状态。
- 程序化恢复选区不得生成新的高亮，也不得绕过当前自动翻译设置。
- 点击或拖动页面中的普通文字仍使用 PDFKit 的常规选区行为；高亮不得阻止用户重新选择包含它的文字。
- 页面高亮的右键菜单提供“删除高亮”。删除一条跨页高亮时，其全部页面片段同时移除。

## 高亮列表与检查器

### 检查器模式

右侧检查器顶部提供“翻译 / 高亮”切换：

- 应用启动时默认显示“翻译”，不持久化上次模式；
- 普通 PDF 划词和点击页面高亮会切换到“翻译”；
- 添加高亮后仍停留在“翻译”；
- 用户主动切换到“高亮”后，显示当前论文的高亮列表；
- 切换检查器模式只改变展示内容，不取消翻译任务、不删除译文，也不改变自动翻译设置。

### 列表内容

- 只列出当前论文的高亮。
- 按文档顺序排列：先按起始页码，再按该页中的起始位置；不按创建时间排序。
- 每项显示起始页码和一至两行原文预览。
- 预览可以规范化空白以保持紧凑，但记录中的原始文字不得因此被覆盖。
- 跨页高亮在列表中只占一项，可用简短页码范围表达，例如“第 4–5 页”。
- 没有高亮时显示安静的空状态，不提供与 P2 无关的引导或功能入口。

### 列表操作

- 单击列表项时跳转到高亮起始位置并将其置于阅读区中央。
- 列表导航仍停留在“高亮”，不自动切回翻译，便于连续浏览多个标记。
- 列表中的当前项应有明确选中状态；页面中的对应高亮可以加强显示，但不能永久改变其黄色。
- 选中列表项后按 `Delete` 删除；右键菜单同样提供“删除高亮”。
- 删除后列表、页面和持久化数据同步更新；如果删除的是当前项，列表选择移动到合理的相邻项或清空。

## 删除、撤销与重做

删除单条高亮不弹确认框。入口包括：

- 对相同用户选区再次按 `⇧⌘H`；
- 页面高亮的右键菜单；
- 高亮列表的右键菜单；
- 在列表中选中后按 `Delete`。

当前应用会话内支持：

- `⌘Z` 撤销添加或删除高亮；
- `⇧⌘Z` 重做；
- 菜单标题应尽量说明操作，例如“撤销添加高亮”或“撤销删除高亮”。

撤销和重做后的状态同样立即持久化。撤销历史不跨应用重启保存，也不要求恢复移除整篇文献的操作。

## 与文献和文件生命周期的关系

- 高亮通过文献的应用内稳定 ID 归属，不以文件路径作为主键。
- PDF 在同一卷内移动或重命名并由书签自动恢复后，高亮继续保留。
- 通过“重新定位…”恢复当前文献时，高亮继续归属于该文献。
- 重新定位到页数或内容不同的 PDF 时，P2 不承诺自动重锚文本；无法安全显示的片段应跳过并提示，而不是删除原始高亮记录。
- 移除没有高亮的文献时，保持现有直接移除行为。
- 移除含有高亮的文献时，必须先提示“移除后将同时删除 N 条高亮”，提供“取消”和明确的破坏性确认按钮。
- 用户确认移除后，文献引用及其全部高亮一并删除；以后重新导入相同 PDF 不自动恢复这些高亮。
- 移除仍然只影响 Lurume 数据，绝不删除或修改原 PDF。

## 本地数据模型

P2 使用独立于文献库的版本化高亮 JSON 存储。分离存储的目的，是让高亮文件损坏或未来版本不兼容时，文献库、PDF 阅读和翻译仍能继续使用。

高亮快照至少包含：

```text
schemaVersion
highlights[]
  id
  paperID
  rawText
  createdAt
  segments[]
    pageIndex
    rects[]
```

- `id` 是高亮的稳定 UUID。
- `paperID` 对应现有 `PaperRecord.id`。
- `rawText` 保存用户选区原文，用于列表预览和重新翻译，不保存译文。
- `segments` 按选区顺序保存页面索引和逐行页面坐标；起始段同时用于列表排序和跳转。
- 几何数据读取时必须验证有限数值、非空矩形和合理页码，异常片段不得传入 PDFKit。
- 顶层格式从高亮 schemaVersion 1 开始，与文献库 schemaVersion 独立演进。
- 写入采用临时文件和原子替换，避免应用退出或崩溃留下半写文件。
- 添加、删除、撤销和重做每次都生成完整的新快照并立即原子写入；只有写入成功后才发布新的页面和列表状态。P2 不对这些操作采用延迟写入，以免与“落盘后才算成功”的产品约束冲突。

P2 不把高亮存成散落在原 PDF 旁边的 sidecar 文件，也不承诺对外开放 JSON 格式；导出格式在数据模型稳定后另行讨论。

## 实现前技术审查结论

- PDFKit 可以通过 `PDFSelection.selectionsByLine()` 取得逐行选区，通过页面索引和 `bounds(for:)` 保存页面坐标；跨页选区可以汇总为一条包含多个页面片段的逻辑记录。
- 页面显示使用只存在于当前 `PDFDocument` 内存实例中的高亮批注。Lurume 不调用 PDF 写出接口；切换或关闭文献时释放这些临时批注，原文件不发生变化。
- 每个内存批注必须由 Lurume 自己维护的映射关联到稳定高亮 ID，不能把原 PDF 自带的同色批注误认为 Lurume 数据。
- 点击命中、选区右键菜单和页面高亮右键菜单需要由 `PDFView` 的轻量 AppKit 子类承载；SwiftUI 继续负责外壳、检查器和列表。
- 列表跳转和页面高亮点击都可以从保存的逐行矩形重建 `PDFSelection`；前者只导航，后者把重建选区送入现有翻译流程。
- 标准 `UndoManager` 可以承载会话内添加与删除的逆操作；每次撤销或重做仍须先成功写入高亮快照，再更新界面。
- 高亮存储与文献库是两个独立文件，移除整篇文献时不存在文件系统级的跨文件原子事务。实现必须采用预检和失败回退：任一写入失败都显示错误并恢复可见状态，不得报告虚假成功；异常中断后发现的孤立高亮不得自动附着到以后重新导入的文献。

## 异常与只读状态

- 高亮文件不存在时视为尚无高亮并创建新存储。
- 高亮文件损坏、版本高于当前支持或无法安全解码时，不得静默清空或覆盖原文件。
- 顶层 JSON 或版本信息无法解码时，高亮功能进入只读错误状态且不显示未经验证的数据。只有顶层有效、个别记录无法解码时，才显示其余可安全读取的记录；由于再次保存会覆盖坏记录，此时同样整体只读，添加、删除、撤销和重做均不可用。
- 高亮错误不得阻塞文献导入、PDF 阅读、搜索、翻译、元数据编辑或阅读位置保存。
- 单次保存失败时回退对应的内存和页面变化，并保留此前已成功保存的数据。
- 不可显示的单个片段应被隔离并产生非阻塞提示，其余高亮继续可用；不得因为一条坏记录删除整份高亮数据。
- 文献移除与高亮删除必须协调完成；任一步失败时不得向用户呈现“文献已安全移除且高亮已删除”的虚假成功状态。

## 键盘与可访问性

- `⇧⌘H` 只处理当前有效 PDF 文字选区，不抢占文本输入框中的普通编辑。
- `Delete` 只在高亮列表拥有明确选中项且列表处于操作焦点时删除，不影响 PDF 或文献列表的其他行为。
- `⌘Z` 与 `⇧⌘Z` 接入 macOS 标准撤销系统，不使用不可见 SwiftUI 控件模拟快捷键。
- 右键菜单项、检查器切换、列表项和空状态提供可理解的辅助功能标签。
- 仅使用颜色不足以表达列表中的当前项；列表必须同时使用系统选中状态。

## 不纳入 P2

- 多种高亮颜色、颜色含义和颜色筛选
- 高亮笔记、评论、标签和摘录卡片
- 跨文献高亮汇总、全文搜索和智能集合
- 保存或持久化译文、翻译历史和术语表
- 将 Lurume 高亮写回 PDF 或导入原 PDF 的已有批注
- Markdown、纯文本、BibTeX 或其他高亮导出
- 云同步、账户、共享和协作批注
- OCR、手写标注、自由绘图、下划线和删除线
- iOS、iPadOS、多窗口和标签页
- 对被外部替换或重新排版的 PDF 自动重锚高亮

## 验收标准

P2 第一版只有同时满足以下条件才算完成：

1. 对普通单行、多行和跨页文字选区使用右键菜单或 `⇧⌘H`，能够创建一条黄色高亮。
2. 高亮成功后蓝色选区清除，黄色标记立即可见，最后一次译文继续保留。
3. 关闭并重新启动应用后，高亮仍准确显示在原文字位置，原 PDF 的内容和文件哈希不变。
4. 对相同范围再次执行高亮命令不会创建重复项，而是删除已有高亮；部分重叠选区保持为独立记录。
5. 页面高亮可被点击并重新选中原文；自动翻译开启时按当前语言设置翻译，关闭时允许手动翻译。
6. 右侧可以在“翻译”和“高亮”之间切换；切换不会清除译文、取消任务或改变自动翻译设置。
7. 高亮列表只显示当前论文，并按页码和页面位置排序；每项显示正确页码和原文预览。
8. 点击列表项后，PDF 跳转到对应高亮并将其置于阅读区中央，同时列表保持可继续浏览。
9. 可以通过页面右键、列表右键和列表 `Delete` 删除高亮；跨页高亮的全部片段同步删除。
10. 添加和删除可以在当前会话内通过 `⌘Z` 撤销、`⇧⌘Z` 重做，撤销或重做后重启状态与最后一次操作一致。
11. 文件同卷移动、重命名或成功重新定位后，高亮仍归属于原文献；无效片段不会导致应用崩溃或数据被静默删除。
12. 移除含有高亮的文献时显示准确数量和破坏性确认；取消不改变数据，确认后文献引用和高亮均被删除，原 PDF 不受影响。
13. 高亮存储损坏、版本过高或写入失败时不覆盖原数据，PDF 阅读、搜索、翻译和文献库操作继续可用。
14. 扫描 PDF、空白选区和无法解析页面位置的选区不会创建无效高亮。
15. 现有 P0/P1 自动化测试全部继续通过，并新增覆盖持久化往返、坐标校验、重复判定、跨页记录、排序、删除、撤销、迁移隔离和失败回退的测试。

## 验收样本与观察项

除 P0 固定样本外，P2 验收至少增加：

- 一份双栏、可选择文字的普通论文，用于验证逐行高亮不覆盖栏间空白；
- 一份包含页面旋转或不同裁切框的 PDF；
- 一份创建跨页选区的长论文；
- 一份生成数百条高亮的压力样本。

Release 验收记录高亮数据加载耗时、打开含数百条高亮文献的首屏耗时、连续添加和删除时的响应，以及空闲内存变化。P2 先建立可重复基线，不在实现前设定脱离实测的硬性性能数字。

## P2 完成之后

P2 完成后先用真实论文验证高亮是否足以支持回顾。只有当实际使用持续表明需要表达“为什么高亮”时，再讨论笔记；只有当单篇高亮列表不足以找回内容时，再讨论跨文献汇总、标签或导出。多颜色不作为默认的下一步。
