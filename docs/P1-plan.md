# Lurume P1 讨论记录

状态：讨论中  
更新日期：2026-08-27

本文档用于在真实使用 P0 后持续记录 P1 的产品判断。每个主题内区分已经确认的内容与尚待确认的细节；范围冻结前不作为开发规格。

## P1 目标

让 Lurume 从可运行的阅读原型进入能够日常阅读和管理少量论文的阶段。P1 一方面修正真实阅读中已经暴露出的翻译检查器问题，另一方面加入最小文献元数据和文献库整理能力。

## 翻译检查器

### 已确认：以译文为首要内容

当前检查器完整显示原文，并把译文排在原文之后。当选区较长时，译文会被推到可视区域之外，用户必须滚动才能看到最需要的信息。P1 调整为：

- 打开检查器后，译文无需滚动即可优先出现；
- 原文长度不得决定译文的首屏位置；
- 默认完全隐藏原文，不显示原文摘要或截断内容；
- 由文献名和页码标识译文来源，因为清除 PDF 选区后最后一次译文仍会保留；
- 复制原文的能力继续保留，不要求为了复制而先完整展示原文。

### 已确认：启动时直接显示检查器

P0 只有在用户首次选择文字后才自动打开翻译检查器，这会让窗口布局在阅读过程中突然改变，并压缩 PDF 阅读区域。P1 调整为：

- 打开应用主窗口时，右侧翻译检查器默认已经显示；
- 尚未产生选区或译文时显示轻量空状态；
- 首次选择文字只更新检查器内容，不再触发阅读区宽度变化；
- 检查器仍可由用户主动隐藏，以便把窗口空间全部用于 PDF 阅读。

### 尚待确认

- 默认隐藏原文后，文献名和页码负责标识最后一次译文的来源。这些次要信息放在译文上方还是底部，需通过实际使用确认。
- 是否提供按需查看完整原文的入口尚待确认；无论是否提供，复制原文的操作都应始终可用。
- 用户主动隐藏检查器后，下次启动是恢复为默认显示，还是记住用户的隐藏状态，尚待确认。
- 检查器空状态的具体文案和是否提供操作入口待设计；它应保持安静，不抢占阅读注意力。

## 文献元数据

### 自动读取的范围（已确认）

自动元数据来源严格限于 PDF 文件自带的文档属性，读取标题和作者两个字段：

- 导入不等待元数据处理，文件先进入文献库，元数据处理随后完成；
- 元数据只在导入时读取一次，此后不再自动刷新；唯一例外是存量文献库升级时的一次性惰性补全（见“存量文献库升级”）；
- PDF 自带标题满足以下任一条件即视为不可用，回退使用去掉扩展名的文件名，除此之外不做任何启发式判断：
  - 去除首尾空白后为空；
  - 忽略大小写并与原始文件名比较后相同（无论文件名是否带扩展名）；
- 用户手动保存的字段永远优先于 PDF 自带属性，不会被任何自动结果覆盖；
- 不从论文首页正文启发式识别任何信息，也不联网查询；其余排除项见“不纳入 P1”。

### 手动编辑（已确认）

可编辑字段限定为：

- 标题；
- 作者；
- 年份。

年份不设自动来源：PDF 属性中的创建日期通常是编译或下载时间而非发表年份，误标率高，P1 只允许手动填写。

编辑入口遵循 Finder 中“先选择项目，再编辑”的交互习惯：

- 用户先在文献列表中选中一篇文献；
- 右键菜单提供“编辑文献信息…”；
- 按 `Return` 进入标题编辑；
- 标题编辑时再次按 `Return` 保存，按 `Escape` 取消；
- 右键入口打开完整表单，用于同时编辑标题、作者和年份；
- 完整表单提供明确的“保存”和“取消”，不随输入逐字段落盘。

原始文件名、文件位置和导入时间可在文献信息中查看，但不属于论文元数据，不可编辑。其中“文件位置”显示记录中最新的已知路径（随成功打开自动跟随文件移动更新），不单独维护历史版本。

### 尚待确认

- 是否需要 DOI 字段。

## 文献列表与整理

### 列表行版式（已确认）

P0 以 PDF 文件名识别文献；P1 改为以论文标题作为文献列表中的主信息：

- 列表主行显示论文标题；
- 文件名不再占据列表主位置，但继续保存在文件信息中；
- 无法获得可信标题时使用去掉扩展名的文件名作为回退标题；
- 用户应能手动修正自动读取错误或缺失的标题；
- 行提供 tooltip 显示原始文件名，便于区分回退标题相同的文献。

每条文献采用固定的紧凑结构：

```text
论文标题（最多两行）
作者 · 年份（最多一行）
```

- 作者或年份缺失时自动省略缺失项及其分隔符，不显示空占位；
- 作者过长时在一行内截断，不增加列表行高度；
- 文件名不在常规列表行中显示；
- 文件不可用等状态继续通过图标或简短状态标识表达。

### 尚待确认

- 按最近阅读、导入时间和标题排序的选择方式，以及排序选择是否跨启动保存；
- 是否需要年份筛选或分组。

## 文献库搜索（已确认）

- 文献列表顶部提供搜索框；
- `⌘F` 将键盘焦点移到搜索框；`⌘F` 专属于文献库搜索，PDF 内全文搜索继续使用阅读工具栏入口，不绑定 `⌘F`；
- 输入时实时匹配论文标题、作者和原始文件名；
- P1 不搜索 PDF 正文，也不建立全文索引；
- 搜索无匹配时列表显示轻量空状态，不打断键盘输入；
- 清空搜索后恢复完整文献列表；
- 如果当前正在阅读的文献被搜索结果过滤掉，PDF 和翻译检查器继续保持当前内容，不中断阅读；
- 清空搜索后，当前文献重新在列表中出现并恢复选中状态。

## 存量文献库升级（已确认）

P1 将修改文献库格式（schemaVersion 1 → 2）。已有 P0 使用者存在真实数据，升级必须无损：

- 升级时把 P0 的显示名平移为回退标题，稳定标识、书签、页码和各项时间原样保留；
- 旧记录不在升级瞬间批量补读元数据：某篇文献下次成功打开并通过安全作用域解析时，才惰性补读一次 PDF 属性；读取失败或文件不可用时保持现状，不产生错误提示；
- 惰性补全遵守同一条优先级规则：用户手动保存过的字段不会被补全覆盖；
- 文献库格式升级必须在任何自动读取之前完成，升级失败的库应以只读空状态呈现，不得静默清空重建。

## 不纳入 P1

- 在线 DOI、Crossref 和 arXiv 元数据查询；
- 从 PDF 首页正文启发式识别标题、作者或年份；
- 标签、项目和智能文件夹；
- OCR、全文索引和全文搜索；
- PDF 高亮、批注和摘录笔记；
- 引用格式与 BibTeX、RIS、CSL-JSON 导出；
- 云同步、多窗口和标签页。

## 实现注意事项

以下内容不改变范围与交互设计，仅供实现参考：

- 在 SwiftUI 的 `List` 中实现 Finder 式 `Return` 进入行内改名需要自定义焦点管理和按键拦截，动手前先做小型技术验证；如代价过高，及时回到讨论而不是自行改成别的交互。

## P0 观察项的延续

以下 P0 验收记录中的观察项不进入 P1 开发范围，在 P1 期间的真实使用评审中继续观察，若形成持续问题再立项：

- 大型 PDF 连续阅读时 PDFKit 页面缓存的瞬时内存峰值（约 450 MB 后回落）；
- `PDFDocument(url:)` 主线程同步加载是否需要异步化——P0 基线显示 308 页样本打开耗时中位数 0.40 秒，暂无证据支持改造。

## 验收标准草案

### 翻译检查器

- 对跨越多个段落的长选区完成翻译后，检查器打开时首屏可以直接看到译文开头。
- 默认状态不显示原文正文。
- “复制原文”仍复制完整选区。
- 清除 PDF 选区后，最后一次译文、文献名和页码继续保留。
- 首次打开主窗口时翻译检查器已经可见，并显示空状态。
- 首次选择文字时 PDF 阅读区域不因检查器出现而改变宽度。

### 文献元数据与列表

- 导入自带可信标题的 PDF 后，列表主行无需手动操作即显示该标题。
- PDF 标题为空白或与文件名相同时，回退为去掉扩展名的文件名。
- 手动修改标题、作者或年份后重启应用，内容保留且不被 PDF 属性覆盖。
- 完整表单点击取消不写入任何修改；行内编辑按 `Escape` 同样不落盘。
- 作者、年份行在有任一字段时正确拼接分隔符，两者全缺时整行省略。
- 文献行 tooltip 显示原始文件名。

### 文献库搜索

- `⌘F` 将焦点移到文献库搜索框，且不影响 PDF 工具栏内的全文搜索。
- 输入实时匹配标题、作者和原始文件名；无匹配时列表出现空状态。
- 正在阅读的文献被过滤掉时，PDF 与译文内容保持不变；清空搜索后该文献重新出现并恢复选中。

### 存量库升级

- 用 P0 构建并使用过的文献库升级到新格式后，所有文献的引用、阅读位置和时间信息完整保留。
- 升级后旧文献在下次成功打开时显示由 PDF 属性补全的标题；文件不可用的旧文献保持原有名称，无错误弹窗，不阻塞应用。
