# Lurume P0 验收记录

状态：通过
验收日期：2026-08-26

## 结论

P0 规格中的 12 项验收标准均已通过。选择器导入、真实文件拖放、文件判重、JSON
持久化、页码恢复、文件重命名恢复、丢失文件重新定位、PDF 阅读和系统翻译均已在真实
Mac 上验证。损坏、密码保护和扫描型 PDF 不会导致应用退出。

验收过程中修复了三个实际问题：

- PDFKit 初始化期间同步发布状态导致的 SwiftUI 运行时警告；
- 无效 PDF 打开失败后页码栏短暂保留上一份文献页数；
- SwiftUI `URL` 拖放目标无法稳定接收覆盖在 PDFKit 上的系统文件拖放。最终使用透明的
  AppKit 文件拖放接收层处理标准 `public.file-url`，并保留 PDF 阅读区的鼠标交互。

验收期间还调整了源语言识别方案（相应更新了原型规格）：`source: nil` 的系统自动识别
对短选区（单词、缩写）不可靠，且源语言为 nil 时 `prepareTranslation()` 无法触发语言包
下载确认界面。改为由 `NLLanguageRecognizer` 从当前页正文样本识别源语言后显式传入
`TranslationSession.Configuration`；语言包下载改由 `translate(_:)` 触发系统界面。

## 性能基线

测量对象为上述 Release 构建。时间从操作发起计到主窗口工具栏或 PDF 页码状态可交互。
RSS 来自 `ps`，单位为 KB。

| 指标 | 三次结果 | 中位数 |
| --- | --- | ---: |
| 启动到主窗口可交互 | 1.06 s、0.50 s、0.47 s | 0.50 s |
| 选择 308 页 PDF 到首屏可见 | 0.28 s、0.40 s、0.45 s | 0.40 s |

- 普通 PDF 打开并空闲 30 秒：146,752 KB RSS（约 143.3 MiB）。
- 大 PDF 连续前向/反向阅读累计超过 10 分钟：开始 183,920 KB，结束 181,584 KB，
  变化 -2,336 KB（约 -2.3 MiB）。
- 阅读中途抽样观察到 462,832 KB RSS 的 PDFKit 页面缓存峰值，继续翻页后回落到
  275,152 KB，最终回到 181,584 KB。最终占用稳定，但这个瞬时峰值应在后续真实阅读
  评审中继续观察。
- 1.06 秒是重新构建后的首次启动；首次语言包下载成本单独发生，没有混入上述普通启动
  或大 PDF 打开计时。
